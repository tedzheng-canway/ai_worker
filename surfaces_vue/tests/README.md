# 前端功能回归验证

在 `surfaces_vue` 目录运行：

```powershell
npm test
npm run build
npm run test:browser
```

- `npm test` 使用 Node 自带测试运行器，验证设置转换/校验、MCP 参数、历史拒绝状态、上下文用量和自动化完成状态机。
- 浏览器脚本针对上一步生成的 `dist`，启动临时静态服务器，使用 Playwright 拦截 HTTP/WebSocket 并模拟后端响应。不会启动或修改 Python 后端，不会连接实际模型、MCP 或外部服务。
- 浏览器脚本使用本目录 `package.json` 声明的 `@playwright/test`，首次执行前在 `surfaces_vue` 运行 `npm ci`。默认使用本机 Microsoft Edge；可以通过 `P0_BROWSER_CHANNEL=chrome` 使用 Chrome。
- 浏览器覆盖保存失败保留输入、设置回显、MCP 命令参数、历史拒绝状态、用量刷新、会话显示数量、自动审批关闭、模型/角色刷新、切换会话后自动化回写及运行失败不误报成功。
- 浏览器失败时将截图保存在被 Git 忽略的 `surfaces_vue/dist/p0-failure.png`。

## 会话工作区验证范围

会话工作区脚本覆盖 15 个浏览器场景，可运行 `node tests/conversation-workspace.browser.cjs` 单独验证。

- Markdown 标题、表格、代码、产物链接和危险 HTML/链接转义；历史图片恢复、CSV 引号/换行解析、跨模型用量累积。
- 附件选择、移除、拖放、图片粘贴、PDF 页数检查、纯附件发送，以及发送前选择/取消工作目录后保留草稿、附件和技能。
- 根据 `requires_folder` 在进入会话时提示选择目录，未选择时禁止发送；最近目录、手动路径、系统选择器取消、临时目录创建失败与重试、选择成功后等待用户明确发送。同角色新会话复用项目目录，临时目录重新选择；默认角色首次启动的目录选择与服务预设目录恢复。
- Markdown、文本、图片、HTML、PDF、CSV、Excel 预览；目录浏览、系统打开请求及认证头。HTML 隔离预览验证不能访问父页面；PDF 验证实际 canvas 渲染。
- 技能编辑、导入内容预览后确认安装、会话禁用、斜杠菜单和独立 skill 发送字段。
- 重命名、置顶、归档、搜索键盘操作、布局持久化、分组数量限制。
- 思考/回答流保留、错误重试、压缩状态、Token、Todo、上滚阅读和回到底部。工具过程按轮次归组并默认折叠，覆盖实时进展、动作摘要、审批合并、运行/失败状态、原始详情，以及过程说明和最终回答的分离。
- 命令/只读会话/域名/MCP 审批值，审查拒绝后重试，计划反馈及模式，团队聊天、任务详情、目录读写回复，自动审批模式的授权限制。
- 工作区信任/撤销、目录失败保留输入、权限切换、项目看板绑定、临时目录保存后重新连接；窄窗口文件面板无横向溢出。

会话工作区失败截图为 `dist/conversation-workspace-failure.png`，通过时保留 `dist/conversation-workspace-files.png`、`dist/conversation-workspace-narrow.png` 和 `dist/conversation-workspace-setup.png` 供布局检查。工具过程截图为 `dist/tool-turns-collapsed.png`、`dist/tool-turns-desktop.png` 和 `dist/tool-turns-mobile.png`。产物均被 Git 忽略。

这些验证使用模拟服务：不会启动真实模型、打开系统文件管理器或安装实际技能。现有后端接口与 React 参考实现经过静态核对；真实办公任务仍需在用户的本地服务中联调。

项目记忆菜单沿用原版绑定接口，并进入统一记忆管理查看/编辑。后端 `/v1/memory` 只有 `scope`，没有项目键，不能在前端可靠地筛选单个项目的记忆内容。

## 集成与工作流验证范围

集成与工作流脚本覆盖 13 个浏览器场景，可运行 `node tests/integrations-workflows.browser.cjs` 单独验证。

- 云登录/退出、手动字段、托管 OAuth、MCP OAuth 的接口分流；授权失败保留输入，状态刷新后可断开/重新授权。
- Slack 工作区人员、Gmail 默认账号与过滤、HubSpot 隐藏字段；MCP JSON/env/cwd、工具选择、旧信任迁移和逐工具撤销。
- 会话连接器、无人值守与订阅；持久审批替代现场按钮、业务失败重试、已处理查询/会话跳转、目录/计划/问题/工具安装的正确回复格式。
- 区分全局 inbox 与会话 inline 可见性，恢复会话中的 MCP 信任范围选择，切换会话不残留上一会话审批。
- 频道建议/订阅/取消、私信路由、收件箱投递、未路由消息；外部来源卡片保留发送者与频道。
- 复杂 cron、凌晨与每周时间、失败保留输入、缺少计划元数据时不覆盖；既有单次计划只读保留。模板缺少连接器时禁止创建，OAuth 按钮不会意外提交创建表单；修改投递目标需重新勾选授权。
- 持久授权撤销、未读标记、全局运行事件与任务返回路径；成员会话、团队聊天失败重试、认证附件、看板任务关系/阻塞原因及带意见的请求修改。

这些仍是模拟服务验证。没有真实登录第三方、发送消息、运行定时任务或启动 MCP 进程；实际账号授权和投递需在用户环境中联调。

集成与工作流沿用现有接口：已有自动化的时区/单次执行时间不可修改；持久 MCP 信任从审批产生；托管 Slack 审批负责人由安装者管理；未路由列表不可任意重放，但连接器未授权人员的暂存消息可“允许并投递”。

## P0/P1 可靠性验证范围

可运行 `node tests/reliability.browser.cjs` 单独验证以下 4 个场景：

- 实时续接事件、提供商实际输出预算和推理强度，续接耗尽后的截断标记及重试。
- 重新打开会话后的压缩摘要、边界、工作状态、省略计数和带鉴权的完整历史预览，以及窄屏布局。
- 环境变量密钥显示来源并隐藏移除按钮；应用保存密钥保留移除入口。
- Telegram 账号审批人的添加、删除和状态刷新。

基础浏览器脚本同时验证摘要预算的保存、失败保留及刷新回显。后端另以 pytest 覆盖审批越权、凭据与进程锁、工具结果落盘、摘要质量、历史修复、提供商参数降级、停止/唤醒和看板活动去重。

## 自动化完成状态与接口限制

手动运行的后端 `finalize` 接口只确认成功，并验证会话已经正常结束。前端仅在观察到 `turn_end.status=completed` 且随后收到 `turn_done` 时调用；回写失败可重试，同一运行不会并发/重复回写。截断、等待、失败或中断不能被确认成成功。

运行过程中切换会话保留自动化连接；意外断线会重连。浏览器同一标签页刷新后，通过 `sessionStorage` 恢复运行跟踪，且不会重发任务。若断线期间错过了完整结束事件，前端明确提示结果待确认，不根据可能只是部分输出的历史回答猜测成功。

失败、截断或中断的手动运行显示提示，不调用成功接口，因此相应运行记录可能仍为 `running`。后端调度器独立执行的任务会保存实际结束状态，并仅在正常完成时记为成功、发送成功通知。浏览器关闭期间手动运行的可靠结算不由这些模拟浏览器测试保证。
